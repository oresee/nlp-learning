# 测评体系说明

## 为什么要测

这套学习系统的核心是**自适应**：不按固定进度表推，而是根据你的实际掌握情况决定教什么、教多深、跳过什么。测评是唯一的信息来源。

因此有两条硬规则：

1. **不许查资料。** 查了之后的答案反映的是"我能找到答案"，不是"我掌握了"，会让教学计划建立在错误信息上。
2. **不会就写不会。** 猜对一道题，代价是我误以为你掌握了，然后跳过它，最后在阶段 3 崩掉。

## 测评类型

| 类型 | 编号 | 时机 | 形式 |
|---|---|---|---|
| 入门摸底 | `L0` | 开始前 | 笔试，探清真实起点 |
| 模块检测 | `M1-check` 等 | 每个模块结束 | 笔试 + 代码实现 |
| 阶段大考 | `S1-exam` 等 | 每个阶段结束 | 综合项目 + 深度问答 |
| 复查 | `R-*` | 错题 1–2 周后 | 针对错题本，防止假性掌握 |

## 掌握度评级

- **A** — 能独立推导/实现，能解释设计动机，能指出方法局限
- **B** — 能独立实现，理解原理，但对边界情况和设计动机把握不牢
- **C** — 照着资料能做出来，独立做会卡住
- **D** — 只有概念印象

**进入下一模块的门槛是 B。** 拿到 C 不会让你重学整个模块，我会只针对薄弱点补，然后重测。

## 出题原则

好题的标准是：**会背公式的人做不出来，真懂的人能做出来。**
所以你会看到很多"为什么这样设计"、"如果改成 X 会怎样"、"这个看起来的缺点为什么反而是优点"这类题，而不是纯计算和纯定义。

这不是刁难 —— 研究能力的本质就是判断"为什么"和"如果不这样会怎样"。从第一天就按这个标准训练。

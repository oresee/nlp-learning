### 2026-09-07（续）· M1 向量化推导 + 代码实现 — **grad_check 全绿**

**教学方法：维度倒推法。** 核心一句话："梯度的形状必须等于对应变量的形状"（否则 `W - lr*dW` 没法做）。
只演示了 dW2 一项，其余六项由学习者独立完成。

**学习者独立推出的完整反向传播（约定 A）：**
```
dZ2 = (1/m)(A2 - Y)                        (n2, m)
dW2 = dZ2 @ A1.T                           (n2, n1)   ← 我演示的唯一一项
db2 = np.sum(dZ2, axis=1, keepdims=True)   (n2, 1)
dA1 = W2.T @ dZ2                           (n1, m)
dZ1 = dA1 * A1 * (1 - A1)                  (n1, m)
dW1 = dZ1 @ X.T                            (n1, n0)
db1 = np.sum(dZ1, axis=1, keepdims=True)   (n1, 1)
```

**过程中的关键表现：**
- 🌟 **主动发现了我给的式子里的约定不一致** —— 自己提出 `dZ2 = (1/m)(A2-Y)`，
  质疑我演示 dW2 时又乘了一次 1/m。**这是本次最有价值的一次提问。**
  借此讲了约定 A / 约定 B 的区别，以及"两边都乘 → 1/m²、loss 仍会下降只是变慢、极难发现"这个真实 bug。
  **给他定了约定 A**，理由针对性：1/m 只需写一次，之后自动沿链传播，避免他 E4 的老毛病。
- ✅ **dW1、db1 用的是 dZ1 而非 dA1** —— 我没有提醒，他自己走对了。**错题 E5 解决。**
- ⚠️ 第一次 dW1 写成 `X.T @ dZ1` 并标注形状 `(n0,n1)`：**目标形状本身就搞错了**（W1 是 (n1,n0)），
  且该乘法维度非法（`(m,n0)@(n1,m)`）。追问"W1 的形状是什么"后立即自己改对。
  → 说明维度倒推法他会用，但**第一遍容易凭手感写完再补形状**，而不是先定形状再摆积木。已当场纠正。
- ⚠️ db1 形状标成 `(n0,1)`，应为 `(n1,1)`。式子对，标注错。

**顺带教的通用规律（他都追问出来了，不是我硬塞的）：**
- **前向广播 ↔ 反向求和**（源于他问"b 为什么是 1 列不是 m 列"）。
  连带讲清了 b 是模型参数、m 是 batch 大小，两者必须解耦，否则模型无法泛化 / 无法变 batch size。
- `axis=k` 的含义是"第 k 维消失"；`keepdims=True` 必加，否则 `(n2,)` 与 `(n2,1)` 广播成 `(n2,n2)`，
  **不报错但结果全错** —— 强调了这类"静默错误"比崩溃更危险。
- numpy 向量化思维：布尔数组当掩码。埋了伏笔到阶段 2 的 causal mask。

**代码实现（`00-foundations/numpy_mlp/mlp.py`）：**
- 踩坑 1：`if Z1 > 0: dZ1 = dA1` → `ValueError: truth value of an array is ambiguous`。
  **这是真实的理解缺口**（把 numpy 数组当标量），不是笔误。讲了"不要对元素写控制流，要对数组写表达式"。
- 踩坑 2：把 Python 代码直接粘进 PowerShell → ParserError。教了 `python -c` 与 REPL 的区别。
- 最终实现干净，**`1/m` 只出现在 dZ2 一处，没有重复乘**（这是本次最关键的检查点，通过）。
- 提醒了 PEP 8 空格问题（`1/m*(A2-Y)`、`(Z1>0)`），未深究。

### 2026-09-07（续）· M1 三道思考题 —— **M1 结业判定**

**Q1. 训练集/测试集准确率差距说明什么？** —— 评级 **C+**

学习者答："说明就算训练集 100% 也不一定会让测试集全对。"
→ **这是对现象的复述，不是解释。** 补讲了三层：
1. 训练集准确率基本无参考价值（模型见过这些数据），测试集才是唯一诚实的指标
2. 两者之差叫**泛化差距**；本次 1.11%，很小，泛化良好
3. 🌟 **测试集只有 360 个样本，98.89% 意味着错 4 个。4 个样本的差异是噪声还是真实差距？**
   正确说法是"在 360 样本的分辨率下这两个数区分不开"。
   → 这条是**研究基本功**（论文里最常见的水分就是拿这种量级的差异宣称更优），后续要反复强化。

**Q2. hidden 32 → 256？** —— 预测 **错**（但错得有价值）

学习者预测："训练集更高，测试集可能因过拟合变差。"
实际：`100.00% / 98.89%` → `100.00% / 98.89%`，**一个数都没变**；仅 cost 0.006236 → 0.004276。
→ 补讲：容量根本不是瓶颈，32 已足够；加的是冗余不是能力。
→ **cost 下降 ≠ 准确率上升**（模型只是对已答对的题更自信，跨不过 0.5 阈值）。
→ 点明"参数多 → 过拟合"这条经典直觉在深度学习里不成立，埋了 double descent / 缩放定律的伏笔（阶段 3）。

**Q3. lr 0.5 → 5.0？** —— 结论蒙对，**机制说反了**

学习者预测："损失会有很大波动，可能卡在比较差的地方。"
实际：cost **精确冻结**在 `0.693128`，小数点后六位一动不动；准确率 50.31% / 46.67%。
→ **不是波动，是死亡。** 我实际解剖了网络验证：

```
lr = 0.5  →  A1 中 >0 元素占比  47.07%    dW1 最大绝对值  6.25e-04
lr = 5.0  →  A1 中 >0 元素占比   0.00%    dW1 最大绝对值  0.00e+00
```

**dying ReLU**：步子太大 → 所有 Z1 < 0 → A1 全零 → `dZ1 = dA1*(Z1>0) = 0` → dW1 恒为 0 → 永久死亡。
🌟 **直接接上了他在 L0-B2 自发提出的 Leaky ReLU** —— 当时只是直觉，现在看到了它防的是什么。

**0.693128 这个数（重点，已作为诊断信号教给他）：**
A1 全零 → `Z2 = b2` → 输出与输入无关的常数 → b2 滑到训练集正类比例。实测验证：
```
A2 取值范围        [0.496868, 0.496868]   ← 确实是常数
训练集正类占比 p    0.4969                 ← 完全吻合
H(p)               0.693128               ← 与观测值一致
ln(2)              0.693147
```
> **二分类交叉熵卡在 0.693（=ln2）→ 模型在输出常数，什么都没学到。**（多分类对应 `ln(类别数)`）

**🌟 顺带教的工程原则（针对他工程调试 D 的短板，这是补起来的第一块砖）：**
`train.py` 打印了"⚠️ 代价几乎没降。backward 大概率还是错的" —— **这是误报**，他的 backward 经 grad_check 数学验证是对的。
> **有验证过的结论，压倒没验证的猜测。** `grad_check` 是数学上严格的验证；那句警告只是启发式经验规则。冲突时信前者。

# 全局约定

## 数学公式写法（Claude Code 桌面版实测，2026-09-20 定稿）

写任何含数学符号的回答时按这个来 —— 用户明确反馈过排版难读，这条优先级很高。

- **重要公式** → `$$...$$` 独立成行
- **行内数学** → `\(...\)`，**三个条件必须同时满足**：

  1. **`\(` 前面必须是空格或行首。** 中文标点（`：`、`，`、`、`）后面要**补一个空格**。
     紧挨着一律不渲染 —— 实测 8 个位置无一例外。
     结束符 `\)` 后面接 `，。、` 无影响，不用管。
  2. **内容不能是光秃秃一个标识符。** `\(w\)` 会显示成 `(w)`，`\(w_t\)` 显示成 `(w_t)`。
     **裸拉丁变量用 `\mathit{}` 包**：`\(\mathit{w}\)`、`\(\mathit{w}_t\)`、`\(\mathit{g}\)`。
     希腊字母 `\(\beta\)` 和含运算符的式子 `\(x^2 + 1\)` 本身就够，直接写。
  3. ⚠️ **表格单元格里绝不能出现裸竖线** —— Markdown 把它当列分隔符，那一格被劈开、整张表错位。
     绝对值写 `\(\lvert \mathit{w}\rvert\)`（不含竖线字符）；纯文本里必须转义。

- ❌ `$...$` 不渲染；❌ 反引号不包数学，只包代码标识符（`np.sum`、`dW1`）
- ⚠️ **终端版里 `$$` 也不渲染。** 用户说在终端、或反馈看到一堆 `\frac`，就改用代码块包纯文本。

**多步推导拆开排版、留空行、标步骤号。信息密度过高比缺少排版更伤。**

换了客户端（网页版 / IDE 插件 / 手机）后渲染异常 → 用 `math-rendering` skill 重新探测，不要猜。
